# Алгоритмы

Все пороги — константы в начале соответствующего файла; любую можно переопределить
в `~/hack/local_settings.json` без правки кода.

## 1. Табличка — `robot/inspect_vision.py`

1. «Тёмное» = пиксель темнее 72 % локальной средней яркости (окно 41×41) и малонасыщенный → связные компоненты.
2. Кандидат в букву: компонента разумного размера и пропорций, вокруг которой **светлое поле**
   (табличка белая с рамкой). Компоненты внутри рамок ArUco и манометра исключаются.
3. Вырезка нормализуется в 32×32 (сохраняя пропорции) и сравнивается **нормированной корреляцией**
   с шаблонами:
   - буквы, отрисованные несколькими шрифтами (`training/make_plate_templates.py`);
   - реальные вырезки букв с поля.

   Шаблоны встроены в код (base64), отдельные файлы не нужны.
4. Перебор искажений: поворот `ROT_ANGLES = ±15°` (табличка висит криво), растяжение
   по ширине `STRETCH = 1.0 / 1.3 / 1.6` (смотрим сбоку).
5. Алфавит ограничен `PLATE_ALPHABET = "АБВ"`. Пару Б/В корреляция путает, поэтому смотрим
   правый верх буквы (18–40 % высоты, правые 32 % ширины): у В там верхняя петля (чернил > 45 %), у Б — пусто.
6. Ответ принимается, если оценка ≥ `PLATE_MIN_SCORE = 0.75`.

## 2. Манометр — `robot/inspect_vision.py`

1. HSV-маски зелёного и красного (красный — два диапазона по H), склейка морфологией
   (стрелка может разрезать полукруг).
2. Компонента-**полукруг**: ширина ≈ 2 высоты (1.4–2.9), заполняет 55–95 % рамки, видны оба цвета.
   Центр оси (`pivot`) — середина нижнего края, радиус `R` — половина ширины.
3. Стрелка — тёмные малонасыщенные пиксели внутри полукруга; её угол — среднее направление
   этих пикселей от оси, дальние точки (кончик) весомее.
4. Угол **границы цветов** — между краями зелёного и красного секторов (3-й/97-й перцентили углов).
5. Если `|стрелка − граница| < GAUGE_MID_DEG = 7°` → «посередине», иначе цвет сектора,
   в котором стрелка. `margin` на картинке — насколько далеко стрелка от границы (уверенность).

## 3. ArUco — `robot/aruco_detect.py`

- OpenCV `cv2.aruco`, поддерживаются старый (`detectMarkers`) и новый (`ArucoDetector`) API.
- Словарь `DICT_6X6_50`. Если не указать — перебираются все словари (медленно).
- `MIN_MARKER_FRAC = 0.04`: маркеры уже 4 % ширины кадра — с чужих арматур вдали.

## 4. Животные — `robot/animals_detect.py`

- YOLOv8n, вход 320×320 (растяжение без паддинга, как в Roboflow «Stretch»), ONNX, opset 12.
- onnxruntime на CPU Raspberry Pi 4: ~250 мс/кадр.
- Свой декодер выхода + NMS (`NMS_TH = 0.5`).
- Порог `CONF_TH = ANIMAL_CONF = 0.75`.
- **Фильтр «на полу»** (`mission.py`, `ANIMAL_MIN_BOTTOM = 0.65`): низ рамки должен быть ниже 65 %
  высоты кадра. Фигурки стоят у основания арматуры; роботы и люди на фоне — выше.

## 5. Голосование — `robot/mission.py`

- На каждой точке осмотра: стоп, пауза `SETTLE = 0.6` с, `FRAMES = 6` кадров.
- Табличка / маркер / манометр — самый частый непустой ответ.
- Животное «Есть», если найдено хотя бы на `ANIMAL_MIN_SHARE = 40 %` кадров; вид — по большинству.
- Для судей сохраняется `armature_N.jpg` с рамками и уверенностями + все сырые кадры в `raw/`.

## 6. Точка обзора — `reach_view`

Если записанная точка осмотра занята (сугроб, другой робот), пробуем запасные ракурсы
`ALT_VIEWS` — сдвиг по дуге вокруг арматуры на ±30…50° и/или на 10–20 см дальше.
На поиск — не больше `VIEW_BUDGET = 60` с, иначе осмотр с того места, куда доехали.

## 7. Навигация — `robot/nav.py`

**Одометрия.** Скорости из `/odom` интегрируются самостоятельно, с коэффициентами
`ODOM_SCALE` (большие колёса) и `YAW_SCALE`.

**Движение.** Поворот на месте (П-регулятор `K_ANG`), затем езда к точке с удержанием курса
(`K_HEAD`) и замедлением у цели (`K_LIN`), ускорение ограничено `ACCEL`.
Если цель сзади и ближе `REVERSE_MAX = 0.35` м — едем задом без разворота.

**Препятствия по лидару.** Проверяется прямоугольная полоса перед роботом шириной
`2 × ROBOT_HALF_W`. Ближе `SLOW_DIST` — медленно, ближе `STOP_DIST` — объезд:
отворот на `DETOUR_TURN = 45°` в более свободную сторону, `DETOUR_STEP = 0.3` м вбок, новая попытка.
После `SIDE_SWITCH = 3` неудач — другая сторона; после `MAX_DETOURS = 10` — точка пропускается.
Если до цели меньше `GOAL_CLOSE = 0.12` м, помеха = «доехали».

**Застревание.**
- `StuckWatch`: за `STUCK_WIN = 1.2` с сдвинулись меньше 2 см, хотя едем → отъезд `BACKUP`.
- IMU: наклон больше `TILT_DEG = 5°` → наехали на сугроб.
- **SLIP_GUARD**: эталонный скан запоминается каждые ≥5 см пути по колёсам. Если колёса
  «проехали» d, а скан изменился меньше чем на `SLIP_FRAC × d` — буксуем, путь не засчитывается.

**WALL_FIX — поправка по стенкам.** На старте (`init_walls`) замеряем расстояния до стенок
по четырём направлениям (вперёд, влево, назад, вправо от стартового курса). Перед каждой точкой (`relocalize`) — узкий луч (`WALL_CONE = 2°`)
в сторону каждой стенки; расхождение больше `WALL_GATE = 0.35` м считается помехой (стойка, человек),
поправка за раз — не больше `WALL_MAX_FIX = 0.4` м. Большие поправки принимаются, только если
их подтверждают две противоположные стенки.

## 8. Сугробы — `robot/snow.py`

Режим `MODE = "white"`:

1. Яркость пола — по нижним 10 % кадра (`FLOOR_ROWS`).
2. Маска: пиксели ярче пола на `WHITE_DV = 40` и почти без цвета (`S < 30`), ниже `HORIZON = 0.35`.
3. Связные области фильтруются:
   - широкие (`MIN_WIDTH = 20 %` кадра) и низкие (`ширина/высота ≥ 1.8`) — трубы арматуры высокие;
   - целиком ниже `TOP_MIN` — сугроб ниже камеры, а стойки и люди выше;
   - между пятном и полом нет синего борта (иначе это белое за бортом);
   - снизу есть **тёмная кромка** (`REQUIRE_RIM`) — у плоского «льда» её нет.
4. «Впереди сугроб», если ближний край ниже `TRIGGER_Y` и сугроб занимает ≥ `MIN_FRAC` коридора.

В финальном заезде с большими колёсами объезд сугробов был выключен (`--nosnow`).
